# Rule patterns real content skills use

Built from a benchmark of 5 public content skills (LinkedIn, multi-platform,
newsletter). Across them, 53 of 239 rules left no trace in 7 outputs, and the
most missed types were mechanics (22), conditionals (13), voice (8), length (7)
and format (7). Walk this list for every reconstruction. For each pattern,
record evidence in the ledger or write the question under Unknowns.

| # | Pattern | How it hides | What to do |
|---|---|---|---|
| P1 | **AI-tell bans**: "not X, it's Y" reveals, "no X, no Y" lists, rule-of-three triples, neat closing aphorisms, reveal bridges ("Here's the thing"), engagement bait, commenting on the post itself | Clean outputs show nothing | Count each in every output. Zero across all: list "likely banned" as an Unknown question. Never put one of these devices into your own template. |
| P2 | **Per-post caps**: at most 1 contrast, 1 triple, 1 to 2 bold phrases per section, 3 sentences per paragraph, N dividers | Small samples look like a pattern, not a ceiling | Count per output. Write "at most <max seen> (cap unconfirmed)". Never write a range whose top exceeds the max seen. |
| P3 | **Template menu**: named frameworks picked by goal or post type (PAS, how-to, story to lesson, contrarian, case study) | Looks like one conditional rule per brief type | Write a menu entry (name, skeleton, trigger) only for a shape seen in 2+ outputs. A shape seen once is likely the brief, not the skill: ask "is there a menu of shapes, and what picks one?" |
| P4 | **Per-user voice file** (voice.md, about-me, voice guide): tone, hooks, CTAs, banned words supplied by the user | Consistent voice looks fixed | Ask whether style is fixed or user-configured. Recover which slots the file controls, not only the values seen. |
| P5 | **Platform limits in native units**: characters, the "see more" cut, hashtag ranges, words of caption body only | Measured in the wrong unit, or over the wrong span | Measure words and characters, per section. Write a loose range and mark it unconfirmed. |
| P6 | **Optional sections** ("if applicable", "optional", "only if accepted") | Present in N/N outputs, so it looks mandatory | A section that could plausibly be skipped is "usually", with a question about when it is skipped. |
| P7 | **Length tiers** (short, standard, deep) | All outputs land in one band | Ask whether the band is one tier of several. |
| P8 | **Content-triggered formatting**: code blocks, links and anchor text, TL;DR thresholds, tables | Briefs never triggered them | List as Unknowns: "rules for content types the sample does not cover". |
| P9 | **Packaging lost in capture**: code block around the draft, a note explaining choices, alternatives, approval card | Collected outputs keep only the paste-ready text | Ask how the deliverable is handed over. |
| P10 | **Defaults vs bans**: no hashtags, no emoji, spelling variant | Absence looks like a ban | Write as a default ("no hashtags unless the voice uses them") unless the genre base rate makes the absence strong evidence. |
| P11 | **Generator environment**: the person or agent that ran the source skill may have had global style settings (dash bans, plain-sentence rules) | Mechanics in every output, not from the skill | List "mechanics may come from the generator's settings" as an Unknown. Do not make punctuation bans hard rules on output evidence alone. |
| P12 | **Voice-protection rules** in ghostwriting (do not over-polish, never add what the author never uses) | Invisible with an invented author | List as an Unknown question. |
| P13 | **Rotation rules**: "don't reuse a hook pattern from recent posts", "rotate the PS or CTA formula" | Each output looks different, so the slot looks free | For each slot (hook, PS, CTA, close), check whether the device type differs in every output. If yes, write "vary <slot> across posts (rotation unconfirmed)". |
| P14 | **Role skeleton**: every post moves through fixed jobs (reader pain, then proof, then bridge to offer, then payoff) while wording and length change | The form varies, so no fixed skeleton shows | Label each paragraph by its job, not its form. A job sequence present N/N is an observed rule. |
